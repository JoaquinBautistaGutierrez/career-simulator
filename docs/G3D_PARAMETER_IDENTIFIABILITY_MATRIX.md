## 1. Authority and inventory result

This matrix classifies every canonical parameter-path template that actually exists in
[Calibration Parameter Registry](CALIBRATION_PARAMETER_REGISTRY.md), sections 6–7.
The mechanical audit finds **268 templates**, not 275. The same discrepancy exists in
the original G3D-1 commit: its prose said 275 while its canonical tables contained 268.
No duplicate path exists, and comparison with the G3C parameter-contract sections found no
seven omitted normative paths. Therefore this audit does not invent seven identities. Before a
value-bearing candidate is created, registry consumers must adopt the corrected cardinality
`268` (or a later normative change must add genuinely specified paths).

The 186 Calibration Targets, 40 DatasetDefinitions, 139 Golden Vectors and 77 exact
`PT-...-NNN` Product Targets were independently recounted without duplicate IDs.

## 2. Classification contract

| Code | Meaning |
|---|---|
| `A_DIRECT_ESTIMATION_CANDIDATE` | An observational component can be estimated after declared transforms; it is not copied blindly into a causal coefficient. |
| `B_DERIVED_FROM_OBSERVATIONAL_SUMMARY` | A deterministic, versioned derivation/binding is available. |
| `C_JOINT_CALIBRATION_REQUIRED` | Latent or cross-system parameter requires staged joint calibration. |
| `D_PRODUCT_CONSTRAINED_CALIBRATION` | Product targets, not real-world evidence, constrain the value. |
| `E_SYNTHETIC_STRUCTURAL` | Normative algorithm/identity/domain; exact validation replaces calibration. |
| `F_WEAKLY_IDENTIFIED` | Evidence is indirect/selected/private; provisional regularization and sensitivity are mandatory. |
| `G_UNIDENTIFIABLE_V1` | No defensible V1 identification route exists; exclude or close the explicit data/config gap. |
| `H_NOT_REQUIRED_FOR_INITIAL_SLICE` | Path is outside initial slice or tooling-only; absence is explicit, never a default. |

Exactly one primary class is assigned per template. Class F/G rows set
`sensitivityRequired=true`. Wildcards in evidence/target/golden columns denote the exact,
non-empty set of current registry IDs that match that prefix; they are not new IDs.
